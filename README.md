# Finance — личный финансовый трекер (PWA)

Бесплатно, без серверов приложения и регистрации. Основная база хранится на устройстве (IndexedDB), распознавание чеков идёт локально через Tesseract.js (испанский, английский, русский). По желанию можно подключить резервное копирование JSON в Google Drive.

## Команды

| Команда | Что делает |
| --- | --- |
| `npm install` | установить зависимости (один раз) |
| `npm run dev` | разработка на компьютере, http://localhost:5173 |
| `npm run iphone` | собрать и открыть по HTTPS в локальной сети для проверки на iPhone |
| `npm run build` | собрать в папку `dist/` |

## Размещение на GitHub Pages

Всё готово к публикации, но сама публикация делается только вручную.

1. Создайте на GitHub **отдельный** репозиторий, например `finance`. На бесплатном тарифе GitHub Pages работает только с **публичными** репозиториями (для приватного нужен GitHub Pro). В коде нет личных данных, они хранятся только на iPhone.
2. `git remote add origin https://github.com/<user>/finance.git` → `git push -u origin main`.
3. Откройте Settings → Pages → Source: **GitHub Actions**. Workflow `.github/workflows/deploy.yml` соберёт приложение с путём `/<repo>/` и выложит его.
4. iPhone, Safari: `https://<user>.github.io/<repo>/` → «Поделиться» → «На экран „Домой“».

**Обновления.** Каждый `git push` в `main` выкладывает новую версию. Установленное приложение проверяет обновления при открытии и раз в час, затем показывает «Доступна новая версия · Обновить». Переустанавливать ничего не нужно. Данные в IndexedDB при обновлении не трогаются (проверено), номер версии виден внизу «Настроек».

**Важно про данные.** Данные хранятся отдельно для каждого адреса: на `github.io` будет новая пустая база. Чтобы перенести данные, сохраните резервную копию в старой версии и восстановите её в новой. Все проекты на `<user>.github.io` используют один источник (origin), поэтому другие ваши сайты на этом домене технически могут читать его хранилище. Не размещайте там чужой код.

## Доверенный HTTPS для iPhone (один раз)

1. `npm run cert` — создаёт в `.cert/` локальный корневой сертификат и сертификат для IP компьютера (повторите, если IP сменился).
2. `npm run iphone:http` — на iPhone в Safari откройте `http://<IP>:4180/__ca` → «Разрешить» → профиль загружен.
3. iPhone: «Настройки» → «Профиль загружен» → «Установить».
4. iPhone: «Настройки» → «Основные» → «Об этом устройстве» → «Доверие сертификатам» → включите «Finance Local Dev CA».
5. Остановите сервер (Ctrl+C), запустите `npm run iphone`, откройте `https://<IP>:4443` — без предупреждений.

Корневой сертификат ограничен адресами `localhost`, `192.168.x.x`, `10.x.x.x` и не может подтвердить настоящие сайты. Файл `.cert/ca.key` никому не передавайте. После тестов профиль можно удалить: «Основные» → «VPN и управление устройством».

## Как проверить на iPhone

iPhone и компьютер должны быть в одной сети Wi-Fi.

1. На компьютере выполните `npm run iphone`. В консоли появится адрес вида `https://192.168.x.x:4443`.
2. Откройте этот адрес в **Safari** на iPhone. Safari предупредит о сертификате (он самоподписанный и создан только для локальной проверки): «Подробнее» → «Посетить этот веб-сайт».
3. **Камера:** нажмите «Камера», разрешите доступ, сфотографируйте чек. Проверьте:
   - результат появился в форме подтверждения;
   - в приложении «Фото» нового снимка нет (кадр живёт только в памяти и исчезает после сохранения операции).
4. **Из фото:** нажмите «Из фото» и выберите скриншот банковского перевода или фото чека.
5. **Текстом:** введите `Mercadona -42 €` или `MVP +350 €` (для второго сначала создайте клиента MVP).
6. **Установка:** «Поделиться» → «На экран „Домой“». Дальше пользуйтесь значком Finance.
7. **Без интернета:** откройте установленное приложение один раз онлайн и подождите около 30 секунд, пока загрузятся файлы OCR (~20 МБ). Затем включите авиарежим, откройте приложение снова и распознайте чек.

### Важно про iOS

- Safari и приложение на экране «Домой» хранят данные **раздельно**. Работайте в установленной версии.
- Сохраняйте резервную копию: «Настройки» → «Сохранить резервную копию» → «Сохранить в Файлы» / iCloud Drive.
- С самоподписанным сертификатом iOS может не включить офлайн-режим (Service Worker). Камера, распознавание и база работают и так. Для полной проверки офлайна нужен доверенный HTTPS:
  - **локально:** утилита `mkcert` и установка её корневого сертификата на iPhone («Настройки» → «Основные» → «Об этом устройстве» → «Доверие сертификатам»);
  - **или** бесплатный хостинг (GitHub Pages, Cloudflare Pages). Это публикация, она делается только с вашего разрешения.

## Резервное копирование в Google Drive

В «Настройках» нажмите «Подключить Google Drive» и предоставьте доступ `drive.file`. Через 5 секунд после успешно сохранённых изменений приложение обновляет один JSON-файл этой установки в папке `Financy Backup`. Другие установки используют свои файлы. Неизменившиеся данные повторно не загружаются. Ошибки сети не меняют локальную базу, дата последней успешной загрузки и ошибки видны в настройках.

При ограничении `drive.file` вручную созданная папка может быть недоступна приложению. Используется доступная одноимённая папка или создаётся новая `Financy Backup`. Приложение не получает доступ ко всему диску и не удаляет чужие файлы. Повторные загрузки обновляют содержимое файла, сохраняя стандартное управление ревизиями Google Drive.

«Восстановить из Google Drive» открывает список копий, затем показывает сведения о выбранном JSON. Только после нажатия «Объединить» данные объединяются с локальными. Перед этим сохраняется локальный снимок для команды «Вернуть данные до восстановления». Автокопирование приостановлено на время выбора и подтверждения. Исходный формат JSON версии 1 и ручные экспорт/импорт сохранены.

OAuth использует Google Identity Services. Access token хранится только в памяти страницы. После перезапуска приложения или истечения доступа потребуется снова нажать «Подключить Google Drive». Без интернета продолжайте работать локально. На iOS автокопирование выполняется, когда приложение открыто, выполнение в фоне не гарантируется.

### Локальная настройка

1. Создайте `.env.local` по образцу `.env.example` и укажите публичный идентификатор `VITE_GOOGLE_CLIENT_ID`. Client Secret и токены добавлять нельзя. `.env.local` исключён из Git.
2. В Google Cloud Console у Web OAuth Client добавьте origin `http://localhost:4173` без пути. В Consent Screen добавьте тестовый Google-аккаунт и единственный scope `https://www.googleapis.com/auth/drive.file`.
3. В PowerShell выполните `$env:BASE_PATH='/Financy/'`, затем `npm run build` и `npm run preview -- --host localhost --port 4173 --strictPort`.
4. Откройте `http://localhost:4173/Financy/` и подключите Google Drive в настройках. Для проверки используйте тестовые данные. Локальный `localhost` разрешён Google OAuth. Частный Wi-Fi IP не подходит для Web OAuth origin, поэтому сетевой HTTPS-сервер для камеры и локальный OAuth-тест используют разные адреса и отдельные базы.

Перед будущей публикацией добавьте origin `https://<user>.github.io` и repository variable `GOOGLE_CLIENT_ID` в GitHub Actions. Workflow передаёт её сборке как `VITE_GOOGLE_CLIENT_ID`. Это публичный идентификатор, секрет для браузерного клиента не используется. Публикация требует отдельного разрешения.

### Регрессионные проверки

`npm run test:drive` запускает Chrome/Chromium в отдельном профиле с искусственными данными и имитацией GIS/Drive API. Установка зависимостей или вход в реальный Google-аккаунт для этого набора не требуется. При необходимости задайте `CHROME_PATH`. Проверяются debounce, один обновляемый файл, отсутствие лишних загрузок, подтверждение и отмена восстановления, сохранность IndexedDB, ошибки сети, истечение OAuth-доступа, блокировка конкурирующей вкладки и повтор после потерянного ответа сервера. Настоящий OAuth и доступ к Google Drive проверяются отдельно в локальной версии.

## Устройство проекта

- `src/lib/db.ts`: IndexedDB (операции, клиенты, категории, журнал изменений).
- `src/lib/store.ts`: кэш в памяти, действия, мягкое удаление (`deletedAt`), защита от дублей. Поля `updatedAt` и `deletedAt` заложены под будущую облачную синхронизацию.
- `src/lib/backup.ts`: резервная копия JSON (объединение или замена с возможностью отмены), экспорт CSV.
- `src/lib/ocr.ts`: Tesseract.js, предобработка изображения, работа без сети.
- `src/lib/receipt.ts`: разбор текста чека или скриншота: сумма, дата, магазин или получатель, тип операции. Ничего не придумывает: если поле не найдено, оно остаётся пустым и помечается.
- `src/lib/parse.ts`: разбор ручного ввода.
- `scripts/copy-ocr.mjs`: копирует движок и языки OCR в `public/ocr` перед сборкой.
