# Finance — личный финансовый трекер (PWA)

Планирование, модель баланса, совместимость Sync 1.1 и безопасное обновление описаны в [docs/planning.md](docs/planning.md). Обновление установленного сервера и публикация требуют отдельного разрешения.

Бесплатно, без серверов приложения и регистрации. Основная база хранится на устройстве (IndexedDB), распознавание чеков идёт локально через Tesseract.js (испанский, английский, русский). По желанию iPhone синхронизируется с вашим компьютером по домашней Wi-Fi, а компьютер раз в неделю делает резервную копию. Облако не используется.

## Команды

| Команда | Что делает |
| --- | --- |
| `npm install` | установить зависимости (один раз) |
| `npm run dev` | разработка на компьютере, http://localhost:5173 |
| `npm run iphone` | собрать и открыть по HTTPS в локальной сети для проверки на iPhone |
| `npm run build` | собрать в папку `dist/` |
| `npm run test:app` | проверить операции, формы, откат ошибок записи, JSON, OCR, камеру и большую историю на искусственных данных в отдельном браузерном профиле |
| `npm run test:sync-server` / `npm run test:sync` | проверить сервер синхронизации и синхронизацию двух устройств |
| `npm run test:preview` | проверить production preview, подпуть, JS/MIME, Service Worker и офлайн-запуск без переменной BASE_PATH |

### Финальная локальная проверка

Работайте на тестовом адресе, сохраняя прежнюю установленную версию и её данные. HTTP `localhost` подходит для проверки на компьютере. Для камеры и офлайн-PWA на физическом iPhone используйте доверенный HTTPS и одну Wi-Fi-сеть. Смена порта создаёт отдельное хранилище.

1. Выполните `npm run check`, `npm run test:app` и сборку для нужного подпути. Для теста требуется установленный Chrome/Chromium, путь можно задать через `CHROME_PATH`.
2. На главной нажмите «Доход» для пустой формы или «Расход» для выбора камеры, фото и ручного ввода. Экран выбора не должен открывать клавиатуру. Измените сумму, дату и заметку. Дважды быстро нажмите сохранение. После перезапуска должна остаться одна операция с подтверждёнными значениями.
3. Проверьте предупреждение перед удалением, отмену удаления и возврат из корзины. Сохраните JSON и проверьте объединение этой копии без появления дублей.
4. Сфотографируйте чек, выберите фото из галереи, исправьте распознанные поля перед сохранением. Проверьте отказ в доступе к камере и повреждённое изображение. После закрытия камеры индикатор использования камеры должен исчезнуть.
5. На iPhone проверьте поворот, клавиатуру, прокрутку длинных форм и нажатия. Дождитесь готовности к офлайн-работе, включите авиарежим с выключенным Wi-Fi и повторно откройте PWA.
6. После второй локальной сборки проверьте предложение «Обновить», предупреждение при открытой форме и сохранность операций после обновления. Сброс кэша не очищает IndexedDB и ограничен областью Financy.

Подсказки источников появляются только после двух сохранённых неудалённых доходов с одинаковым названием. Регистр и лишние пробелы не создают отдельные подсказки. Проверьте отсутствие подсказки после первой записи, появление после второй, фильтрацию при вводе и заполнение только после явного выбора.

Сводные итоги и графики показываются в EUR. Импортированные операции в другой валюте сохраняют валюту, отображаются в истории и не пересчитываются автоматически. История группируется по местному дню и загружается порциями без ограничения на доступ к старым записям.

## Размещение на GitHub Pages

Всё готово к публикации, но сама публикация делается только вручную.

1. Создайте на GitHub **отдельный** репозиторий, например `finance`. На бесплатном тарифе GitHub Pages работает только с **публичными** репозиториями (для приватного нужен GitHub Pro). В коде нет личных данных, они хранятся только на iPhone.
2. `git remote add origin https://github.com/<user>/finance.git` → `git push -u origin main`.
3. Откройте Settings → Pages → Source: **GitHub Actions**. Workflow `.github/workflows/deploy.yml` соберёт приложение с путём `/<repo>/` и выложит его.
4. iPhone, Safari: `https://<user>.github.io/<repo>/` → «Поделиться» → «На экран „Домой“».

**Обновления.** Каждый `git push` в `main` выкладывает новую версию. Установленное приложение проверяет обновления при открытии и раз в час, затем показывает «Доступна новая версия · Обновить». Переустанавливать ничего не нужно. Данные в IndexedDB при обновлении не трогаются (проверено), номер версии виден внизу «Настроек».

**Важно про данные.** Данные хранятся отдельно для каждого адреса: на `github.io` будет новая пустая база. Чтобы перенести данные, сохраните резервную копию в старой версии и восстановите её в новой. Все проекты на `<user>.github.io` используют один источник (origin), поэтому другие ваши сайты на этом домене технически могут читать его хранилище. Не размещайте там чужой код.

## Доверенный HTTPS для iPhone (один раз)

1. `npm run cert` — создаёт в `.cert/` локальный корневой сертификат и сертификат для IP компьютера (повторите, если IP сменился).
2. `npm run iphone:http` — на iPhone в Safari откройте `http://<IP>:4180/__ca` → «Разрешить» → профиль загружен.
3. iPhone: «Настройки» → «Профиль загружен» → «Установить».
4. iPhone: «Настройки» → «Основные» → «Об этом устройстве» → «Доверие сертификатам» → включите «Finance Local Dev CA».
5. Остановите сервер (Ctrl+C), запустите `npm run iphone`, откройте `https://<IP>:4443` — без предупреждений.

Корневой сертификат ограничен адресами `localhost`, `192.168.x.x`, `10.x.x.x` и не может подтвердить настоящие сайты. Файл `.cert/ca.key` никому не передавайте. После тестов профиль можно удалить: «Основные» → «VPN и управление устройством».

## Как проверить на iPhone

iPhone и компьютер должны быть в одной сети Wi-Fi.

1. На компьютере выполните `npm run iphone`. В консоли появится адрес вида `https://192.168.x.x:4443`.
2. Откройте этот адрес в **Safari** на iPhone. Для камеры и офлайн-PWA используйте доверенный локальный сертификат (настройка описана выше).
3. **Камера:** нажмите «Расход» → «Камера», разрешите доступ, сфотографируйте чек. Проверьте:
   - результат появился в форме подтверждения;
   - в приложении «Фото» нового снимка нет (кадр живёт только в памяти и исчезает после сохранения операции).
4. **Из фото:** нажмите «Расход» → «Из фото» и выберите фото чека.
5. **Вручную:** нажмите «Расход» → «Вручную» или «Доход» на главной и заполните поля. Проверьте возврат без сохранения и подсказки источников после двух доходов.
6. **Установка:** «Поделиться» → «На экран „Домой“». Дальше пользуйтесь значком Finance.
7. **Без интернета:** откройте установленное приложение один раз онлайн и подождите около 30 секунд, пока загрузятся файлы OCR (~20 МБ). Затем включите авиарежим, откройте приложение снова и распознайте чек.

### Важно про iOS

- Safari и приложение на экране «Домой» хранят данные **раздельно**. Работайте в установленной версии.
- Сохраняйте резервную копию: «Настройки» → «Сохранить резервную копию» → «Сохранить в Файлы» / iCloud Drive.
- С самоподписанным сертификатом iOS может не включить офлайн-режим (Service Worker). Камера, распознавание и база работают и так. Для полной проверки офлайна нужен доверенный HTTPS:
  - **локально:** утилита `mkcert` и установка её корневого сертификата на iPhone («Настройки» → «Основные» → «Об этом устройстве» → «Доверие сертификатам»);
  - **или** бесплатный хостинг (GitHub Pages, Cloudflare Pages). Это публикация, она делается только с вашего разрешения.

## Синхронизация с компьютером и резервные копии

iPhone остаётся основным устройством и работает сам: каждая операция сначала сохраняется на телефоне. Если компьютер с Financy Sync включён и подключён к той же Wi-Fi, приложение само отправляет изменения и забирает новые. Это происходит при запуске, при возвращении в приложение, после восстановления сети, через несколько секунд после изменения и раз в 2 минуты, пока Financy открыт. Закрытое приложение iOS в фоне не запускает, поэтому синхронизация идёт только при открытом Financy. Ни облако, ни интернет не нужны.

### Первоначальная настройка (один раз)

1. **Компьютер.** Дважды щёлкните `sync-server\Установить Financy Sync.cmd`. Установщик:
   - копирует сервер в `%LOCALAPPDATA%\Financy-Sync\app`;
   - создаёт папку `D:\CODEX\Financy\Backups`, доступную только вашей учётной записи (при переустановке остаётся папка, которая уже используется);
   - добавляет автозапуск при входе в Windows (без службы и без прав администратора);
   - добавляет правило брандмауэра для портов 47820–47821 в частных сетях, только если вы ответите «Y»;
   - открывает страницу сервера `http://127.0.0.1:47822`.
   Нужны Node.js 22+ и Git for Windows (из него берётся `openssl`). Сеть Wi-Fi в Windows должна быть «Частной».
2. **Сертификат на iPhone.** На странице сервера указан адрес вида `192.168.1.20`. В Safari на iPhone откройте `http://192.168.1.20:47820` и нажмите «Скачать сертификат». Затем «Настройки» → «Профиль загружен» → «Установить». После этого «Основные» → «Об этом устройстве» → «Доверие сертификатам» → включите «Financy Sync CA». Сертификат ограничен адресами `*.local`, `localhost` и частными IP, поэтому не может подтверждать настоящие сайты.
3. **Подключение.** На странице сервера нажмите «Получить код». В Financy откройте «Настройки» → «Подключить компьютер», введите адрес и 6-значный код. Код одноразовый и действует 10 минут. После пяти неверных попыток он блокируется.

Если IP компьютера изменится, сервер сам выпустит новый сертификат. Приложение найдёт компьютер по имени `имя-компьютера.local` или по последним известным адресам. Проверка соединения: `sync-server\Проверить Financy Sync.cmd`. Отключение автозапуска: `Отключить Financy Sync.cmd`, данные и копии при этом не удаляются.

### Как это защищено

- iPhone создаёт ключ P-256, который нельзя извлечь, и подписывает им каждый запрос. Компьютер хранит только открытый ключ. Паролей и токенов в открытом виде нет ни на телефоне, ни на компьютере.
- Соединение идёт по HTTPS. Подпись покрывает метод, путь, время, одноразовый nonce и хэш тела запроса, поэтому повтор, подмена или запрос с чужого устройства отклоняются. Подключённое устройство можно отключить на странице сервера.
- Страница управления доступна только с самого компьютера (`127.0.0.1`).

### Надёжность

- У каждой записи постоянный ID, время изменения, ревизия на сервере и SHA-256-хэш. Целостность проверяется при отправке и получении.
- Сервер подтверждает приём только после записи на диск: временный файл, `fsync`, переименование, предыдущая копия `.prev`. Если ответ потерялся, повторная отправка ничего не дублирует.
- Изменения разных полей одной записи на двух устройствах объединяются. Если одно поле изменено по-разному, остаётся более новая версия, а вторая сохраняется. В «Настройках» появится «Изменено на двух устройствах», где можно выбрать нужную версию. Правка всегда побеждает одновременное удаление.
- Удаления «мягкие» и синхронизируются как удаления. Вся база телефона никогда не заменяется базой компьютера.

### Резервные копии на компьютере

- Папка `D:\CODEX\Financy\Backups` (исключена из Git). Если диска D: нет, используется `Документы\Financy-Backups`. Файлы называются `financy-backup-ГГГГ-ММ-ДД_чч-мм-сс-weekly.json`.
- Полная копия создаётся раз в неделю. Если компьютер был выключен, копия создаётся после ближайшей синхронизации с iPhone. Ещё можно нажать «Создать копию сейчас».
- Каждая копия проверяется после записи. Только после этого удаляются копии Financy старше 30 дней. Последняя исправная копия, повреждённые файлы и чужие файлы в папке не удаляются никогда.
- Формат совпадает с ручным JSON-экспортом (`finance-pwa`, версия 1) и дополнен счётчиками, метаданными синхронизации и хэшем целостности. Файл можно восстановить и вручную через «Восстановить из копии».
- **Восстановление:** «Настройки» → «Резервные копии на компьютере» → копия → просмотр: что вернётся, что изменится, что останется → «Восстановить». Перед этим создаётся защитная копия на компьютере и снимок на iPhone, доступный через «Вернуть данные до восстановления». Записи, добавленные после копии, не удаляются. Автоматического восстановления нет.

### Проверки

`npm run test:sync-server` проверяет сервер: подпись, повтор, замок кода, сбой записи на диск, конфликты, отключение устройства, копии, хранение 30 дней и перезапуск. `npm run test:sync` проверяет два «устройства» в отдельных профилях Chrome с настоящим сервером во временной папке: первая синхронизация, отключение и возврат сети, повторная отправка, одновременные правки, удаление, сбой записи в IndexedDB, восстановление копии и перезапуск сервера.

## Фактуры (Facturas)

Фактуры создаются в разделе «Клиенты» кнопкой «Создать фактуру» и хранятся только на устройстве и, если подключён компьютер, в Financy Sync. Интернет не нужен: PDF собирается на iPhone.

### Настройка (один раз)

- **«Настройки» → «Мои реквизиты».** Имя или название, NIF/NIE/CIF (проверяется контрольный символ), адрес, email, телефон, IBAN (проверяется контрольная сумма), логотип. Профилей может быть несколько.
- **«Настройки» → «Нумерация и налоги».** Введите номер, с которого продолжить: если последняя выставленная фактура была F-0025, введите F-0026. Префикс и количество цифр берутся из примера, ведущие нули сохраняются. Можно завести несколько серий. Там же задаётся IVA по умолчанию. IRPF в каждой новой фактуре равен 0 %; удержание указывается в самой фактуре, итог пересчитывается сразу. Срока оплаты в фактурах нет.

### Как работает нумерация

- Номер присваивается только при окончательном выставлении. Черновики номеров не занимают.
- Стартовый номер можно менять, пока в серии нет ни одной выставленной фактуры. Потом нумерация идёт сама; для другой нумерации создайте новую серию. Выставленные фактуры никогда не перенумеровываются.
- Номера серии выдаёт одно устройство (то, где серия создана), чтобы два устройства без связи не выдали один номер. Передать серию другому устройству можно вручную. Сервер дополнительно отклоняет повтор номера в серии.
- Аннулированная фактура сохраняет номер, он больше не используется. Исправленные фактуры (rectificativas) выпускаются в отдельной серии R-.
- Восстановление из резервной копии не удаляет и не меняет выставленные фактуры и не сдвигает нумерацию назад.

### Клиенты и деньги

- Реквизиты клиента: фото документа, фото или скриншот из галереи, или вручную. Текст распознаётся на устройстве; заполняются только найденные поля, их нужно проверить. Обычные клиенты работают без реквизитов.
- Выставление фактуры не добавляет доход. «Отметить оплаченной» связывает фактуру с уже добавленной операцией дохода или создаёт одну новую. Одна операция оплачивает только одну фактуру, поэтому доход не учитывается дважды.
- Статусы: черновик, выставлена, оплачена, аннулирована.
- «Описание услуги»: при нажатии на пустое поле открывается список услуг из прежних фактур, самые частые сверху; при вводе список фильтруется. Одинаковые названия (без учёта регистра и пробелов) не повторяются. Хранятся только названия, цена не подставляется. Новая услуга появляется в списке после сохранения фактуры или черновика.

### Юридические требования

PDF содержит поля полной фактуры по статье 6 Real Decreto 1619/2012: номер и серию, дату, данные и NIF обеих сторон, описание, базу, ставку и сумму IVA, удержание IRPF, итог. Financy **не реализует VERI*FACTU** (цепочка хэшей, QR-код, журнал, декларация соответствия). По Real Decreto-ley 15/2025 VERI*FACTU обязателен для autónomos с 1 июля 2027 года (для компаний с 1 января 2027). До этой даты нужно либо доработать Financy, либо выставлять фактуры в бесплатном приложении AEAT. Соответствие требованиям уточняйте у своего gestor.

Синхронизация фактур требует Financy Sync 1.2.0 или новее: обновите сервер на компьютере файлом `sync-server\Установить Financy Sync.cmd` (данные, подключённые устройства и папка копий сохраняются). Со старой версией сервера фактуры остаются на iPhone и отправятся после обновления.

`npm run test:invoices` проверяет обновление базы, нумерацию, оплату, аннулирование, исправленные фактуры, восстановление копий, распознавание реквизитов и PDF.

## Устройство проекта

- `src/lib/db.ts`: IndexedDB (операции, клиенты, категории, журнал изменений).
- `src/lib/store.ts`: кэш в памяти, действия, мягкое удаление (`deletedAt`), защита от дублей. Поля `updatedAt` и `deletedAt` заложены под будущую облачную синхронизацию.
- `src/lib/backup.ts`: резервная копия JSON (объединение или замена с возможностью отмены), экспорт CSV.
- `src/lib/ocr.ts`: Tesseract.js, предобработка изображения, работа без сети.
- `src/lib/receipt.ts`: разбор текста чека или скриншота: сумма, дата, магазин или получатель, тип операции. Ничего не придумывает: если поле не найдено, оно остаётся пустым и помечается.
- `src/lib/parse.ts`: разбор ручного ввода.
- `scripts/copy-ocr.mjs`: копирует движок и языки OCR в `public/ocr` перед сборкой.
