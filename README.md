# Finance — личный финансовый трекер (PWA)

Бесплатно, без серверов приложения и регистрации. Основная база хранится на устройстве (IndexedDB), распознавание чеков идёт локально через Tesseract.js (испанский, английский, русский). По желанию можно подключить резервное копирование JSON в Google Drive.

## Команды

| Команда | Что делает |
| --- | --- |
| `npm install` | установить зависимости (один раз) |
| `npm run dev` | разработка на компьютере, http://localhost:5173 |
| `npm run iphone` | собрать и открыть по HTTPS в локальной сети для проверки на iPhone |
| `npm run build` | собрать в папку `dist/` |
| `npm run test:app` | проверить операции, формы, откат ошибок записи, JSON, OCR, камеру и большую историю на искусственных данных в отдельном браузерном профиле |
| `npm run test:preview` | проверить production preview, подпуть, JS/MIME, Service Worker и офлайн-запуск без переменной BASE_PATH |

### Финальная локальная проверка

Работайте на тестовом адресе, сохраняя прежнюю установленную версию и её данные. HTTP `localhost` подходит для проверки на компьютере. Для камеры и офлайн-PWA на физическом iPhone используйте доверенный HTTPS и одну Wi-Fi-сеть. Смена порта создаёт отдельное хранилище.

1. Выполните `npm run check`, `npm run test:app` и сборку для нужного подпути. Для теста требуется установленный Chrome/Chromium, путь можно задать через `CHROME_PATH`.
2. На главной нажмите «Доход» для пустой формы или «Расход» для выбора камеры, фото и ручного ввода. Экран выбора не должен открывать клавиатуру. Измените сумму, дату и заметку. Дважды быстро нажмите сохранение. После перезапуска должна остаться одна операция с подтверждёнными значениями.
3. Проверьте предупреждение перед удалением, отмену удаления и возврат из корзины. Сохраните JSON и проверьте объединение этой копии без появления дублей.
4. Сфотографируйте чек, выберите фото из галереи, исправьте распознанные поля перед сохранением. Проверьте отказ в доступе к камере и повреждённое изображение. После закрытия камеры индикатор использования камеры должен исчезнуть.
5. На iPhone проверьте поворот, клавиатуру, прокрутку длинных форм и нажатия. Дождитесь готовности к офлайн-работе, включите авиарежим с выключенным Wi-Fi и повторно откройте PWA.
6. После второй локальной сборки проверьте предложение «Обновить», предупреждение при открытой форме и сохранность операций после обновления. Сброс кэша не очищает IndexedDB и ограничен областью Financy.

Подсказки источников появляются только после двух сохранённых неудалённых доходов с одинаковым названием. Регистр и лишние пробелы не создают отдельные подсказки. Проверьте отсутствие подсказки после первой записи, появление после второй, фильтрацию при вводе и заполнение только после явного выбора.

Сводные итоги и графики показываются в EUR. Импортированные операции в другой валюте сохраняют валюту, отображаются в истории и не пересчитываются автоматически. История группируется по местному дню и загружается порциями без ограничения на доступ к старым записям.

## Размещение на GitHub Pages

Всё готово к публикации, но сама публикация делается только вручную.

1. Создайте на GitHub **отдельный** репозиторий, например `finance`. На бесплатном тарифе GitHub Pages работает только с **публичными** репозиториями (для приватного нужен GitHub Pro). В коде нет личных данных, они хранятся только на iPhone.
2. `git remote add origin https://github.com/<user>/finance.git` → `git push -u origin main`.
3. Откройте Settings → Pages → Source: **GitHub Actions**. Workflow `.github/workflows/deploy.yml` соберёт приложение с путём `/<repo>/` и выложит его.
4. iPhone, Safari: `https://<user>.github.io/<repo>/` → «Поделиться» → «На экран „Домой“».

**Обновления.** Каждый `git push` в `main` выкладывает новую версию. Установленное приложение проверяет обновления при открытии и раз в час, затем показывает «Доступна новая версия · Обновить». Переустанавливать ничего не нужно. Данные в IndexedDB при обновлении не трогаются (проверено), номер версии виден внизу «Настроек».

**Важно про данные.** Данные хранятся отдельно для каждого адреса: на `github.io` будет новая пустая база. Чтобы перенести данные, сохраните резервную копию в старой версии и восстановите её в новой. Все проекты на `<user>.github.io` используют один источник (origin), поэтому другие ваши сайты на этом домене технически могут читать его хранилище. Не размещайте там чужой код.

## Доверенный HTTPS для iPhone (один раз)

1. `npm run cert` — создаёт в `.cert/` локальный корневой сертификат и сертификат для IP компьютера (повторите, если IP сменился).
2. `npm run iphone:http` — на iPhone в Safari откройте `http://<IP>:4180/__ca` → «Разрешить» → профиль загружен.
3. iPhone: «Настройки» → «Профиль загружен» → «Установить».
4. iPhone: «Настройки» → «Основные» → «Об этом устройстве» → «Доверие сертификатам» → включите «Finance Local Dev CA».
5. Остановите сервер (Ctrl+C), запустите `npm run iphone`, откройте `https://<IP>:4443` — без предупреждений.

Корневой сертификат ограничен адресами `localhost`, `192.168.x.x`, `10.x.x.x` и не может подтвердить настоящие сайты. Файл `.cert/ca.key` никому не передавайте. После тестов профиль можно удалить: «Основные» → «VPN и управление устройством».

## Как проверить на iPhone

iPhone и компьютер должны быть в одной сети Wi-Fi.

1. На компьютере выполните `npm run iphone`. В консоли появится адрес вида `https://192.168.x.x:4443`.
2. Откройте этот адрес в **Safari** на iPhone. Для камеры и офлайн-PWA используйте доверенный локальный сертификат (настройка описана выше).
3. **Камера:** нажмите «Расход» → «Камера», разрешите доступ, сфотографируйте чек. Проверьте:
   - результат появился в форме подтверждения;
   - в приложении «Фото» нового снимка нет (кадр живёт только в памяти и исчезает после сохранения операции).
4. **Из фото:** нажмите «Расход» → «Из фото» и выберите фото чека.
5. **Вручную:** нажмите «Расход» → «Вручную» или «Доход» на главной и заполните поля. Проверьте возврат без сохранения и подсказки источников после двух доходов.
6. **Установка:** «Поделиться» → «На экран „Домой“». Дальше пользуйтесь значком Finance.
7. **Без интернета:** откройте установленное приложение один раз онлайн и подождите около 30 секунд, пока загрузятся файлы OCR (~20 МБ). Затем включите авиарежим, откройте приложение снова и распознайте чек.

### Важно про iOS

- Safari и приложение на экране «Домой» хранят данные **раздельно**. Работайте в установленной версии.
- Сохраняйте резервную копию: «Настройки» → «Сохранить резервную копию» → «Сохранить в Файлы» / iCloud Drive.
- С самоподписанным сертификатом iOS может не включить офлайн-режим (Service Worker). Камера, распознавание и база работают и так. Для полной проверки офлайна нужен доверенный HTTPS:
  - **локально:** утилита `mkcert` и установка её корневого сертификата на iPhone («Настройки» → «Основные» → «Об этом устройстве» → «Доверие сертификатам»);
  - **или** бесплатный хостинг (GitHub Pages, Cloudflare Pages). Это публикация, она делается только с вашего разрешения.

## Резервное копирование в Google Drive

В «Настройках» нажмите «Подключить Google Drive» и предоставьте доступ `drive.file`. Используется исключительно существующая папка `Financy Backup`, ID `13nWwLQw-6-Czl2rc75a4NwKnmIp00sp5`. Сначала проверяется её прямой доступ. Новые папки и одноимённые альтернативы не создаются.

Через 5 секунд после сохранённых изменений создаётся или обновляется `financy-backup-YYYY-MM-DD.json` за местный календарный день устройства. Неизменившийся снимок повторно не загружается, включая переход на новый день. Офлайн-изменения остаются в IndexedDB и отправляются после события online или повторного подключения при следующем запуске.

Хранятся последние 30 календарных дней, включая сегодняшний. Очистка начинается только после загрузки и повторного чтения/проверки новой копии. Только принадлежащие приложению ежедневные файлы с проверенным JSON за пределами окна переносятся в корзину Drive. Прежние файлы, чужие файлы, повреждённые и неоднозначные копии не удаляются автоматически. Ошибка очистки не отменяет успешный бэкап; очистка повторится без повторной загрузки неизменившегося JSON. Локальные финансовые записи при этом не изменяются.

Если прямой запрос папки возвращает 403/404, scope `drive.file` не даёт подтверждённого доступа к указанной папке. Минимальное дополнение — однократно выбрать именно её через Google Picker того же Cloud project: включить Google Picker API и задать публичный браузерный `VITE_GOOGLE_PICKER_API_KEY` с ограничением HTTP referrers (включая `https://docs.google.com/*`, поскольку Picker работает в iframe). Полный scope `drive` и Client Secret не нужны. Без ключа прямой доступ продолжает работать; если он закрыт, копирование приостанавливается с точным сообщением.

Повторные сохранения и потерянный ответ сервера используют тот же ID файла. При потере настроек файл повторно обнаруживается в указанной папке. Если сегодняшняя удалённая копия отличается от локального снимка или обнаружено несколько кандидатов, автоматическая перезапись останавливается до выбора и объединения пользователем. Одновременная работа разных устройств может создать конфликт файлов: приложение сохраняет обе копии и сообщает о нём, не удаляя данные автоматически.

«Восстановить из Google Drive» открывает список копий, затем показывает сведения о выбранном JSON. Только после нажатия «Объединить» данные объединяются с локальными. Перед этим сохраняется локальный снимок для команды «Вернуть данные до восстановления». Автокопирование приостановлено на время выбора и подтверждения. Исходный формат JSON версии 1 и ручные экспорт/импорт сохранены.

OAuth использует Google Identity Services Token Client с popup; дополнительные Redirect URI не требуются. Access token хранится только в памяти страницы. После перезапуска приложения или истечения доступа потребуется снова нажать «Подключить Google Drive». На iOS автокопирование выполняется, когда приложение открыто, выполнение в фоне не гарантируется. Для iPhone нужен разрешённый HTTPS-домен; локальные Wi-Fi IP не подходят и блокируются до загрузки OAuth. Если Safari блокирует popup, разрешите всплывающее окно для этого сайта и повторите вход. Авторизация в Safari по другому адресу не подключает хранилище установленной PWA.

### Локальная настройка

1. Создайте `.env.local` по образцу `.env.example` и укажите публичный идентификатор `VITE_GOOGLE_CLIENT_ID`. Client Secret и токены добавлять нельзя. `.env.local` исключён из Git.
2. В существующем Web OAuth Client уже настроены origins `http://localhost:4173` и `https://danil200891-jpg.github.io`, тестовый аккаунт и scope `https://www.googleapis.com/auth/drive.file`. Повторно создавать OAuth client не нужно.
3. В PowerShell выполните `$env:BASE_PATH='/Financy/'`, затем `npm run build` и `npm run preview -- --host localhost --port 4173 --strictPort`.
4. Откройте `http://localhost:4173/Financy/` и подключите Google Drive в настройках. Для проверки используйте тестовые данные. Локальный `localhost` разрешён Google OAuth. Частный Wi-Fi IP не подходит для Web OAuth origin, поэтому сетевой HTTPS-сервер для камеры и локальный OAuth-тест используют разные адреса и отдельные базы.

Preview определяет подпуть из уже собранного `dist/index.html`, даже если `BASE_PATH` не сохранён в новой сессии терминала. Не пересобирайте `dist` во время незавершённого обновления открытой PWA. При новой сборке используйте предложение «Обновить», не очищайте IndexedDB или localStorage.

Для будущей публикации workflow использует repository variable `GOOGLE_CLIENT_ID` как `VITE_GOOGLE_CLIENT_ID`. Необязательные `GOOGLE_PICKER_API_KEY` и `GOOGLE_PROJECT_NUMBER` нужны только для Picker; номер проекта по умолчанию берётся из Client ID. Публикация и публичный HTTPS-стенд для новой версии на iPhone требуют отдельного разрешения. Действующий сайт без публикации этой сборки остаётся прежним.

### Регрессионные проверки

`npm run test:drive` запускает Chrome/Chromium в отдельном профиле с искусственными данными и имитацией GIS/Drive API. Установка зависимостей или вход в реальный Google-аккаунт для этого набора не требуется. При необходимости задайте `CHROME_PATH`. Проверяются прямой доступ к фиксированной папке, отсутствие создания папок, дневные копии и 30-дневное окно через смену даты/DST, безопасная очистка и её повтор, debounce, потерянный ответ загрузки, восстановление с подтверждением, сохранность IndexedDB, offline/online, отказ и истечение OAuth, конкурирующая вкладка, дубликаты и повторное подключение. Настоящий OAuth и доступ к Google Drive проверяются отдельно в локальной версии.

## Устройство проекта

- `src/lib/db.ts`: IndexedDB (операции, клиенты, категории, журнал изменений).
- `src/lib/store.ts`: кэш в памяти, действия, мягкое удаление (`deletedAt`), защита от дублей. Поля `updatedAt` и `deletedAt` заложены под будущую облачную синхронизацию.
- `src/lib/backup.ts`: резервная копия JSON (объединение или замена с возможностью отмены), экспорт CSV.
- `src/lib/ocr.ts`: Tesseract.js, предобработка изображения, работа без сети.
- `src/lib/receipt.ts`: разбор текста чека или скриншота: сумма, дата, магазин или получатель, тип операции. Ничего не придумывает: если поле не найдено, оно остаётся пустым и помечается.
- `src/lib/parse.ts`: разбор ручного ввода.
- `scripts/copy-ocr.mjs`: копирует движок и языки OCR в `public/ocr` перед сборкой.
